# BYOK key verification and extraction endpoints

Checked 2026-09-29 against vendor docs and against live unauthenticated/bogus-key calls to the production APIs. Covers Supadata, Jina Reader, Firecrawl, Tavily. Related: `13-multimodal-capture-apis.md`.

## Supadata

- Auth header is `x-api-key: <key>`; the OpenAPI spec declares a single `apiKeyAuth` scheme and base URL `https://api.supadata.ai/v1`. A `Authorization: Bearer` header is ignored — a live call with only `Authorization: Bearer …` returned `401 {"details":"Missing API Key"}`. [Transcript OpenAPI](https://docs.supadata.ai/api-reference/endpoint/transcript/transcript.md), [Get transcript](https://docs.supadata.ai/get-transcript.md)
- **A key-verification endpoint exists.** `GET https://api.supadata.ai/v1/me` takes no parameters and returns `{organizationId, plan, maxCredits, usedCredits}`. Documented status codes are 200/401/500 only. The docs do not state a credit cost for it and it is filed under Account Information rather than a billed service. This is the endpoint to call at save time; it also yields remaining credits for free. [Account Information](https://docs.supadata.ai/api-reference/endpoint/account/me.md)
  - Caveat: the absence of a credit charge is inferred from the docs not listing one. Not stated affirmatively anywhere primary.
- Errors share one body shape: `{error, message, details, documentationUrl}`. [Error codes](https://docs.supadata.ai/errors/list.md)
- Invalid vs out-of-credits **is** distinguishable, on both status and `error` code:
  - Invalid/missing key → `401`, `error: "unauthorized"`. Live, `/v1/me` with no key returned `{"error":"unauthorized","message":"Unauthorized","details":"Missing API Key",…}`; with a bogus key, `details: "Invalid API Key: sd_bogus_000"`. Same body from `/v1/transcript`. [Unauthorized](https://docs.supadata.ai/errors/unauthorized.md)
  - Out of credits → `429`, `error: "limit-exceeded"`, `details: "Plan usage limit was exceeded."` The same code and status also cover throttling, with `details` of `"Global request rate limit was exceeded."` or `"Request rate limit on current plan was exceeded."` — so quota vs throttle can only be told apart by the `details` string, which is brittle. Prefer `usedCredits`/`maxCredits` from `/v1/me` for the quota signal. [Limit exceeded](https://docs.supadata.ai/errors/limit-exceeded.md), [Error codes](https://docs.supadata.ai/errors/list.md)
  - A plan-gated feature returns `402 upgrade-required`, distinct from both. [Error codes](https://docs.supadata.ai/errors/list.md)
- `GET /v1/transcript?url=…` accepts YouTube, TikTok, Twitter, Instagram, Facebook and direct media file URLs. Optional `lang`, `text` (default `false`), `chunkSize` (50–10000), `mode` ∈ `native` | `auto` | `generate` (default `auto`; forced to `generate` for file URLs). [Transcript OpenAPI](https://docs.supadata.ai/api-reference/endpoint/transcript/transcript.md)
  - `200` → `{content, lang, availableLangs}`; `content` is a string when `text=true`, otherwise timestamped chunks.
  - `202` → `{jobId}`, returned when the video is too large to process inline. Poll `GET /v1/transcript/{jobId}`, which returns `{status, content, lang, availableLangs}` or `{status, error}` with `status` ∈ `queued` | `active` | `completed` | `failed`. Results expire one hour after completion. [Get transcript](https://docs.supadata.ai/get-transcript.md)
  - **No transcript available is a soft result, not a failure:** `206` with `error: "transcript-unavailable"`, and it still costs 1 credit. Hard failures are the ordinary 4xx/5xx codes. Treat 206 as "captured, no transcript" rather than an error path. [Transcript unavailable](https://docs.supadata.ai/errors/transcript-unavailable.md), [Get transcript](https://docs.supadata.ai/get-transcript.md)
- `GET /v1/metadata?url=…` covers the same five platforms and returns one unified schema regardless of platform: `{platform, type, id, url, title, description, author{username,displayName,avatarUrl,verified}, stats{views,likes,comments,shares}, media, tags, createdAt, additionalData}`. For YouTube, `additionalData.channelId` is populated and `title` is set; for an Instagram reel, `title` is `null` and the caption lands in `description`. 1 credit per request on all platforms. [Metadata](https://docs.supadata.ai/get-metadata.md)
- Free plan: 100 credits/month, no card, 1 request/second. [Pricing](https://supadata.ai/pricing)

## Jina Reader

- Auth is `Authorization: Bearer <key>`, and **the key is optional** — a live `GET https://r.jina.ai/https://example.com` with no auth returned `200` with `x-ratelimit-limit: 20, 20;w=60`. [Reader](https://jina.ai/reader/)
- Rate limits: 20 RPM without a key, 500 RPM with a free or paid key, 5000 RPM premium. Billing counts output tokens; the live response carried `x-usage-tokens: 796`. [Rate limits](https://jina.ai/api-dashboard/rate-limit)
- **No documented key-verification or balance endpoint.** `api.jina.ai/v1/user`, `/v1/me` and `/api/v1/user` all returned `404 {"detail":"Invalid endpoint"}` live. The dashboard's own balance call, `GET https://embeddings-dashboard-api.jina.ai/api/v1/api_key/user?api_key=…`, does respond (`401 {"detail":"Invalid API key."}` for a bogus key) but is undocumented — do not depend on it. Verify a Jina key by making a real Reader call against a cheap URL instead.
- Invalid key → `401` with `{"data":null,"code":401,"name":"AuthenticationFailedError","status":40102,"message":"Invalid API key, please get a new one from https://jina.ai","readableMessage":"…"}` (live response).
- Extraction endpoint: `GET https://r.jina.ai/<TARGET_URL>` (or `POST https://r.jina.ai/` with `url=<TARGET_URL>` for hash-routed SPAs). Send `Accept: application/json` for a structured body; `x-respond-with` selects `markdown` (default), `html`, `text`, `screenshot`, `pageshot`, `frontmatter`. Live JSON response: `{"code":200,"status":20000,"data":{"title","description","url","content", …}}`. [Reader README](https://github.com/jina-ai/reader#readme)
- A free-token grant for new keys could not be confirmed from any primary Jina page; the pricing and dashboard pages state rate limits but no token allowance. Do not assume one.

## Firecrawl

- Auth is `Authorization: Bearer fc-…`, base URL `https://api.firecrawl.dev`. A key is required for every endpoint. [API reference](https://docs.firecrawl.dev/api-reference/introduction)
- **A key-verification endpoint exists and is free.** `GET https://api.firecrawl.dev/v2/team/credit-usage` returns `{"success":true,"data":{"remainingCredits","planCredits","billingPeriodStart","billingPeriodEnd"}}`. It is a billing inquiry, not a scrape, so it costs no credits. Use it at save time; `remainingCredits` doubles as the quota check. [Credit usage](https://docs.firecrawl.dev/api-reference/v2-endpoint/credit-usage)
- Invalid key → `401 {"success":false,"error":"Unauthorized: Invalid token"}`, confirmed live on both `/v2/scrape` and `/v2/team/credit-usage`. Quota and rate-limit breaches surface as `429`, so the two are cleanly separable. [API reference](https://docs.firecrawl.dev/api-reference/introduction)
- Extraction endpoint: `POST https://api.firecrawl.dev/v2/scrape` with `{"url":"https://example.com","formats":["markdown"]}`. Returns `200` with `data.markdown` (string) and `data.metadata` carrying `title`, `description`, `language`, `sourceURL`, `url` (post-redirect), `keywords`, `statusCode`, `contentType`, `error`. [Scrape](https://docs.firecrawl.dev/api-reference/v2-endpoint/scrape)
- Free plan: 1,000 credits/month, refreshed monthly, no card; 10 req/min on `/scrape`, `/map`, `/search`, 2 concurrent browsers. [Pricing](https://www.firecrawl.dev/pricing)

## Tavily

- Auth is `Authorization: Bearer tvly-…`, base URL `https://api.tavily.com`. A key is required. [Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)
- **A key-verification endpoint exists and is free.** `GET https://api.tavily.com/usage` explicitly consumes no credits and returns both key-scoped and account-scoped counters: `{key:{usage, limit, search_usage, extract_usage, …}, account:{current_plan, plan_usage, plan_limit, paygo_usage, paygo_limit, …}}`. Best-in-class for this purpose — one call gives validity, plan and headroom. [Usage](https://docs.tavily.com/documentation/api-reference/endpoint/usage)
- Invalid key → `401 {"detail":{"error":"Unauthorized: missing or invalid API key."}}`, confirmed live on both `/extract` and `/usage`. Quota states have their own codes: `429` rate limit (with `Retry-After`), `432` plan limit exceeded, `433` pay-as-you-go limit exceeded. Fully distinguishable from an invalid key. [Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)
- Extraction endpoint: `POST https://api.tavily.com/extract` with `{"urls":["https://example.com"]}` (1–20 URLs). Options: `query`, `chunks_per_source` (1–5, default 3), `extract_depth` (`basic` default | `advanced`), `include_images`, `include_favicon`, `format` (`markdown` default | `text`), `timeout` (1–60s), `include_usage`. Response: `{results:[{url, raw_content, images, favicon}], failed_results:[{url, error}], response_time, usage:{credits}, request_id}` — a `200` can still carry failures in `failed_results`, so both arrays must be read. [Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)
- Free plan: 1,000 credits/month, no card. `extract_depth=basic` costs 1 credit per 5 successful URLs, `advanced` costs 2. [API credits](https://docs.tavily.com/documentation/api-credits)

## Verification limits

Every `401` body above was observed live with a deliberately invalid key on 2026-09-29; no valid credentials were used, so `200` bodies for authenticated endpoints (`/v1/me`, `/v2/team/credit-usage`, `/usage`, `/v2/scrape`, `/v1/transcript`, `/v1/metadata`) are taken from vendor documentation, not from an observed response. Out-of-credits, `206 transcript-unavailable`, `429`, `432` and `433` responses were likewise not reproduced live. The `202` + `jobId` transcript path and the one-hour job expiry are documented but unobserved. Jina's free-token grant and Supadata's credit cost for `/v1/me` are unconfirmed. Re-verify against a real key before relying on any of these shapes in code.
