# Startup resume positioning: backend + AI roles, India/US

Last verified: 2026-10-04

Scope: rewrite positioning research only. Do not edit resume. Target: Indian/US startups hiring roughly 20-30 LPA India roles or early-mid backend + AI roles.

Sources: live YC Work at a Startup pages, Wellfound/Ashby job posts, and YC hiring/resume guidance. Hard evidence below is from role descriptions. Opinion is marked separately.

## Bottom line

Position the resume as **backend engineer who ships production AI systems**, not "AI/ML engineer" and not generic full-stack. The strongest recurring signals are Python/FastAPI or Django, Postgres/SQL plus Redis/queues, cloud/Docker/CI, RAG/agents/tool use, evals/observability, latency/cost control, and end-to-end product ownership.

## Positioning recommendations

These are judgment calls from the evidence above.

1. Headline: **Software Engineer, Backend + AI Systems**. Avoid "AI Engineer" unless resume has serious model/eval/RAG ownership; avoid "Full Stack" unless frontend is central to target roles.
2. Summary: 2 lines max. Say backend production systems first, AI systems second. Example shape: "Backend engineer building Python/TypeScript services, data pipelines, and production LLM/RAG features. Strong in APIs, Postgres, queues, observability, and shipping ambiguous startup work end-to-end."
3. Skills: split by context, not long dump. Suggested groups: Backend, Data, AI Systems, Infra, Frontend. Keep AI skills only if backed by bullets/projects.
4. Experience bullets: use `Built/owned X using Y, resulting in Z`. If Z is unavailable, use scale/proof: users, latency, throughput, cost, reliability, deployment, incident, adoption.
5. For each role/project, include one production signal: monitoring, evals, tests, CI, tracing, error handling, cost controls, DB query/debugging, queue/backoff, auth/security.
6. AI bullets should sound operational: "RAG pipeline with chunking/retrieval/evals", "LLM tool workflow with structured outputs and retries", "reduced token cost/latency", not "integrated OpenAI API".
7. Projects matter if they are recent and demoable. Keep 1-2 strong projects with GitHub/demo/users; remove old/unrelated projects.
8. Show startup fit with ownership language: shipped, owned, debugged, talked to users/founders, scoped ambiguous work, ran production.
9. If no brand-name companies, add one-line context for each company/product: what it did, users/customers, scale, funding, or business domain.
10. Mention AI coding tools only as workflow/judgment: reviewed generated code, used agents to accelerate delivery, wrote tests/evals. Do not make it the achievement.

## Resume rewrite checklist

- Top third must say: backend + production AI + strongest stack.
- Every recent experience has 3-4 bullets max.
- First bullet under strongest role should be most impressive shipped system.
- Include Python/FastAPI or Django only where actually used.
- Include Postgres/SQL, Redis/queues, Docker/cloud if real.
- Include RAG/agents/evals/tool use/structured outputs only with evidence.
- Add links: GitHub, live demo, technical writeup if strong.
- Remove filler: "passionate", "hard-working", "quick learner", "responsible for".
- Replace task bullets with ownership and outcome.
- Keep one-page unless senior depth clearly needs two.

## Gaps / caution

- Wellfound salary data is job-post data, not a market compensation survey; treat it as evidence that the range exists, not that it is guaranteed.
- Ashby posts often hide salary for India roles; use them for requirement evidence, not compensation.
- Some current AI job descriptions are noisy and hype-heavy. Weight repeated concrete requirements higher: backend, production, RAG/evals, observability, latency/cost, ownership.
