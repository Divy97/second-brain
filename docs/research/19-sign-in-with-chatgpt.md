# Sign in with ChatGPT: can users spend their own ChatGPT plan?

Last verified: 2026-10-01

Sources: primary only. The devkit repo `openai/sign-in-with-chatgpt-devkit` (README, LICENSE, `docs/security.md`, `packages/local/src/*`; cloned at commit `f723814`, 2026-09-29) and OpenAI's docs under https://developers.openai.com/siwc. Doc pages were fetched with WebFetch on 2026-10-01; WebFetch returns a model-written extract, so quotes from doc pages are as returned by the tool and should be re-read on the page before they go into a contract or external message. LICENSE and source quotes were read from the raw files.

## Bottom line

Not usable for this app today. The ChatGPT-plan-usage capability is documented only for open-source apps running on the user's own machine. The plan-usage sign-in requires an HTTP loopback redirect on `127.0.0.1` and states "Server-side/remote redirects are not allowed". A paid, remotely hosted web app is not covered; OpenAI points those apps to an interest form. The devkit licence is noncommercial and the docs show no self-serve path to a commercial client ID. Next step: decide whether to submit the interest form (needs a founder decision, since it is a relationship and contract matter). Until OpenAI answers in writing, plan on our paid plans or BYO OpenRouter key.

## Missed by the earlier claims

- Tokens (`/siwc/token-sharing-open-source/token-reference`): access token about one hour (`expires_in: 3600`); refresh token 30 days, replaced on each refresh with a fresh 30 days. Refresh tokens stay server-side and never reach a browser callback. Errors `refresh_token_reused`, `refresh_token_invalidated`, `refresh_token_expired`, `invalid_grant` mean clear tokens and re-run OAuth (errors-and-recovery). `docs/security.md`: rotated tokens must not be reused.
- Server-side token storage is not addressed for plan usage. The only documented storage is local OS-encrypted storage. For the separate website identity flow, the docs say the backend exchanges the code and must not return ID token, PKCE verifier, code or client secret to browser JavaScript, and should issue its own `HttpOnly; Secure; SameSite=Lax` cookie (`/siwc/website`).
- Host identity: apps must persist a stable `ext_agent_host_id` per host (sign-in page). One host ID per installation is a poor fit for a multi-tenant server.
- Usage cap (`profiles-and-sessions`): Plus users have a "five-hour usage limit shared across all apps where they use their ChatGPT plan"; Pro users have no five-hour restriction. Expect users to hit 429s from other apps.
- Remaining errors: `subscription_sharing_usage_unavailable` 503, `..._unsupported_capability` 400, `..._route_not_supported` 403, `..._invalid_user` 401, `..._user_unavailable` 503, `chatpass_v2_scope_not_authorized` 403. "OpenAI won't silently failover to alternative billing"; preserve status, code and request ID (errors-and-recovery).
- Branding and copy (`ui-ux-guidelines`): primary CTA "Continue with ChatGPT"; first-sign-in notice "You're using your ChatGPT plan"; permanent settings option; "Using ChatGPT plan" near the composer; "Manage usage" must open https://chatgpt.com/settings/usage; limit modal "Usage limit reached"; pricing page must say which tiers support it. Licence Section 5 grants no rights to OpenAI marks or branded assets.
- Revocation for transferred (VM) sessions and per-host usage attribution are "not yet available" (self-hosted-vms). The programme is labelled preview.
- The devkit repo is `"private": true` and `"license": "SEE LICENSE IN LICENSE"` in `packages/local/package.json`, so it is not published as a reusable dependency.

- Whether the interest form leads to a hosted or server-side flow, and what it costs or requires. The form page itself was not fetched.
